# Problem list for throughput_probe.sh: one `edition/division/problem` per line.
#
# The set is chosen for the *code path* a problem exercises, not for its
# benchmark status, so a change to demodulation or subsumption shows up as a
# throughput movement on a known shape rather than as a solved-count wobble.
# The sample is a fixed stride over each sorted directory, so it is stable when
# the corpus grows and needs no RNG seed to reproduce.
#
# Recorded per row: the SZS status plus `processed`, `generated`, `passive`,
# `lrs_discarded`, `weight_discarded` and `fwd_subsumed`. `processed` is the
# headline; the rest say *why* it moved, which a solved count cannot.
#
