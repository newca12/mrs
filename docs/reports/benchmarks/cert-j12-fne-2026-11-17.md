# CASC-J12 FNE campaign and strict re-audit (2026-11-17)

> The 75-row FNE campaign produced **46 raw `Theorem` answers**. Its original
> strict audit reported 9 `VerifiedGood` and 37 `Unknown`; 36 of those Unknowns
> were missing-`Axioms/` include errors caused by the audit child replacing
> `TPTP` with the selected-problem directory. After commit `637f396` removed that
> override, a replay of the same run and problem-corpus digests under local TPTP
> v10.0.0 reported **40/46 `VerifiedGood`, 6 `Unknown`, and 0 `VerifiedBad`**.
> This is not an exact J12 v9.0.0 re-audit or a canonical CASC score: the
> producer tree was dirty, its host had 54,198 MB effective memory against the
> 131,072 MB allowance, and the re-audit used a newly built verifier.

## Search results

The campaign completed all 75 selected FNE rows. The `run.csv` statuses are:

| Raw SZS status | Count | Share |
|:---|---:|---:|
| `Theorem` | **46** | **61.3%** |
| `Timeout` | 16 | 21.3% |
| `GaveUp` | 11 | 14.7% |
| `Error` | 2 | 2.7% |
| **Total** | **75** | **100%** |

J12's FNE budget is 180 seconds. Although `run_meta.json` records a 120-second
default, this campaign used `--casc-times`; `run.log` confirms `fne=180s` and
the per-row timeouts are 180 seconds.

The two `Error` rows, `NLP260+1` and `NLP262+1`, ended with `SIGKILL` during
preparation. The recorded cause is **unconfirmed**; the host's lower-than-
configured memory is relevant context but does not establish that the OS OOM
killer caused either termination. `SYN986+1.004` timed out during preparation.

The run used `mrs-starexec` with automatic division routing. It selected
`casc_fne`, with strategy IDs `[11, 13, 4, 8, 15, 7, 3, 1]`, eight workers,
cross-strategy sharing disabled, and one campaign job. This is an observation
from that schedule and build, not a strategy-promotion experiment.

## Strict audit and TPTP include fix

The archived audit under `certification/` used `checks=[strict]` and reported:

| Archived strict result | Count |
|:---|---:|
| Applicable refutations | 46 |
| `VerifiedGood` | 9 |
| `VerifiedBad` | 0 |
| `Unknown` | 37 |
| N/A: incomplete search | 27 |
| Generation errors | 2 |

Thirty-six Unknowns said that an included `Axioms/*.ax` file could not be read;
the other Unknown, `LCL660+1.005`, was a CNF definition-matching limitation.
At producer commit `9c10581`, `audit_casc_proofs::run_check` set the child's
`TPTP` to `args.problems_dir`. That directory contains the selected CASC-J12
problem files, not the TPTP `Axioms/` library, so the child lost the TPTP root
recorded by the campaign. Commit `637f396` removes that override. The audit
continues to pass the staged problem directory separately through
`--problems-dir`.

The fixed replay is in
`certification-reaudit-tptp-v10-20261117/`, leaving the archived original audit
intact. It used the local J12 problem corpus and
`TPTP=/home/hack/TPTP-v10.0.0`. The new audit identity has the same `run.csv`
SHA-256 and problem-corpus SHA-256 as the original audit:

| Fixed strict result | Count |
|:---|---:|
| Applicable refutations | 46 |
| `VerifiedGood` | **40** |
| `VerifiedBad` | **0** |
| `Unknown` | 6 |
| Verifier timeout / proof omitted | 0 |
| N/A: incomplete search | 27 |
| Generation errors | 2 |

All 36 missing-include errors disappeared. Thirty-one of those proofs now
certify; five reach an arithmetic evaluation resource limit instead. The six
remaining Unknowns are:

| Problems | Strict-audit reason |
|:---|:---|
| `CSR113+11`, `CSR113+5`, `CSR115+3`, `CSR116+13`, `CSR116+4` | Unsupported interpreted formula `c0`: arithmetic evaluation resource limit |
| `LCL660+1.005` | CNF node `c162` cites definition bodies that could not be matched against the source |

The replay therefore certifies 40 of the 46 emitted refutations (87.0%). This
is the result of the fixed harness with the rebuilt verifier and TPTP v10.0.0;
it is not a controlled comparison isolating only the environment-variable
change. J12's published TPTP release is v9.0.0, and the audit identity records
the TPTP path but does not hash the included library tree. Treat this as a
corrected local replay, not an exact v9.0.0 certification count or an official
score.

To repeat the local replay without replacing the identity-bound original audit,
use a fresh `CERT_OUT`:

```bash
RUN=/path/to/campaign-casc-j12-fne-W8CASCHJ1-99-20261117
TPTP=/path/to/TPTP-v10.0.0
CERT_OUT="$RUN/certification-reaudit-tptp-v10-$(date +%Y%m%d-%H%M%S)"
nix develop -c env TPTP="$TPTP" CERT_JOBS=4 CERT_OUT="$CERT_OUT" \
  ./crates/mrs-bench/certification_campaign.sh \
  --audit-only "$RUN" --edition casc-j12
```

## Comparability

The November 13 full J12 run also recorded 46 raw FNE theorems; 45 are common
to the November 17 set. `NUN068+1` appears only in the November 17 run, while
`SYO604+1` appears only in the November 13 run. This is an unpaired raw-status
comparison, not a schedule effect: the producer commits and binaries differ,
the adapters differ (`mrs` versus `mrs-starexec`), both producer trees were
dirty, and the November 17 host had substantially less memory. An exploratory
sum of per-problem times on the 45 common solves was 1,036.256 s versus 379.147 s
(an apparent 2.73x reduction); it must not be presented as a measured speedup
or causal portfolio effect.

`MRS_HARDWARE=casc` configured eight workers and a 131,072 MB memory allowance,
but it does not pin the process to eight cores. This host had 16 physical cores
and 63,763 MB RAM; the prover reported 54,198 MB effective memory and
`mem_unrepresentable=1`. The run therefore did not provide the full CASC memory
allowance and is not a canonical eight-core CASC measurement.
