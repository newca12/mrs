# EPS: from 12/100 to 36/100

> Status: current. Measured on commit `9132b1e` (branch
> `feat/eps-casc-sim-exploration`) against `crates/mrs-bench/problems/casc-30`
> with `MRS_HARDWARE=casc-sim`, `--casc-times` (120 s for EPS), and the
> `MRS_WORKERS=2` dual-search split. The before/after numbers are the
> certified track, which was the only source of EPS coverage.

## The finding

EPS asks for `Satisfiable`. Nothing in the ordinary portfolio can produce
it: `given_clause.rs` returns `GaveUp` even for a cleanly saturated clause
set, because the engine is not yet proven complete with respect to indexing,
simplification and cancellation. So EPS coverage came entirely from
`--certify-ordered`, and that path answered 12/100.

Almost none of the other 88 was a search-power problem. The certified path
could not *reach* an answer, and the symptom was identical in every case: a
run that spends its whole budget and reports `GaveUp`. `TRACE_CERTIFY=1`
separated them into three causes.

## Cause 1 — the closure held the whole budget and then skipped the SAT tier

`certify_ground_ordered_resolution` routed with

```rust
if tier1 {
    return run_tier1(..);   // hard return
}
```

`run_tier1` computes a double ordered-resolution closure, which is
exponential in the grounding size. On a grounding that clears the Tier-1
size gate it therefore cannot close — and when it gave up it returned
`Limit`, which propagated straight out of the router. Tier 2, the CaDiCaL
path that decides the *same ground CNF* propositionally, was unreachable for
precisely the inputs it was written for.

Measured, GRP125-2.004:

| | before | after |
|---|---|---|
| grounded clauses | 1133 | 199 (see cause 2) |
| closure growth | 11603 clauses, 304k inferences in 15 s, no close | not attempted |
| Tier 2 | never reached | 10 ms, model re-verified |
| verdict | `GaveUp` at 107 s | `Satisfiable` at 0.01 s |

Tier 2 now runs first. The encoding is linear in a grounding that is already
materialized, so the call is cheap even on the small groundings the closure
can close, and a satisfiable verdict is re-checked clause by clause against
the problem so it does not depend on an ordering at all. Tier 1 keeps the
whole remaining budget for the direction only it can perform — a refutation
carrying TSTP ancestry — and Tier 2's UNSAT falls through to it.

## Cause 2 — the grounder enumerated renaming duplicates

`ground_with_constants` instantiated every clause over every constant: `n^k`
instances for a `k`-variable clause. Instances that are variable renamings
of each other are the *same clause*.

Restricted variable renaming orders a clause's variables by first occurrence
and the domain by symbol id, then requires the value of the *i*-th variable
not to precede the *i-1*-th. That is exactly the non-decreasing value
sequences — one representative per orbit of the renaming group — so the
count becomes `C(n + k - 1, k)`.

| regime | `n^k` | `C(n+k-1,k)` |
|---|---|---|
| 2 constants, 100 vars/clause (KRS, HWV-ar, SYO) | overflow | ~101 |
| 13 constants, 8 vars/clause | 815M | 126k |
| 4 constants, 4 vars/clause (GRP) | 256 | 35 |

Over the 2026-09 casc-30 EPS corpus this takes **40 infeasible groundings
down to 28**. The `2^100 → 101` line is why: that half of the division is
made of clauses with a hundred variables each, and no amount of budget
reaches a grounding that cannot be materialized.

This is an equivalence, not a heuristic, and the tests say so: sorting any
instance's values in first-occurrence order yields a generated one, so every
instance is covered, and renaming-duplicates change neither satisfiability of
the ground set nor the existence of a resolution proof. Two consequences
worth recording:

- The domain is sorted and deduplicated *inside* `ground_with_constants`
  rather than by its callers. The enumerator's `low` index is a
  `partition_point` over that list, and testing found that an unsorted
  domain silently produced non-canonical instances. Trusting the caller here
  would make the one property that makes this sound depend on every call site.
- `first_occurrence_vars` replaced the by-id ordering `free_vars` returns.

## Cause 3 — non-unit positive equalities were refused outright

`expand_equality` rejected any clause with a positive equality literal
beside others, on the grounds that the closure cannot generate the predicate
congruence axioms such a literal would need. It does not need them: a ground
equality between two distinct class representatives is *false*, and a
negative one is *true*, by the unique-name axiom. Deciding them there means
nothing unresolved ever reaches a tier, and the two tests that pinned the
refusal were asserting behaviour that was stronger than it needed to be.

The NLP set is built from clauses that carry `Y = Z` as one literal among a
dozen, so all three NLP problems were in the refused class. Separately, the
EPR gate for Tier 2 was consulted on the *originals*, so a refusal there
also aborted Tier 1 and Tier 3; it now uses `is_epr_input`, the honest
input-side check, and only skips the SAT tier.

## What this exposed

`build_model_certificate` gave every constant its own domain element. For a
clause set containing a unit equation `a = b` — consumed by the union-find
pass, which rewrites every occurrence to one class representative and drops
the now-reflexive literal — that emits a certificate asserting `a != b`. The
`Satisfiable` verdict was correct; the model justifying it was not. This
predates the 2026-09 work.

The class map is now threaded from `expand_equality` to the builder, which
interprets each constant as its representative's element — the reading under
which the dropped disequalities are actually true. The builder additionally
re-derives the requirement from the originals instead of trusting its caller,
because this failure mode is a silent wrong answer on a `Satisfiable` verdict
rather than a crash.

## Two casc-sim defects found while measuring

**An undersized host turned the memory allowance into an OOM kill.** A
casc-shaped mode asks for 128 GB. On a host with less, the OOM killer got
there before the watchdog, so the harness recorded a kill — no SZS status at
all — rather than a resource limit, which is the opposite of what casc-sim
exists to surface. The watchdog now enforces `effective_memory_mb` (the
allowance clipped to what the host has) rather than the nominal allowance. On
a host that can represent 128 GB the two are equal, so a competition-shaped
run is unaffected.

**The dual search blocked on both tracks.** GRP123-4.004 is answered by the
certified track in 113 ms, and the run was reported as 109.498 s because
`invoke.sh` waited for the portfolio track to use its full budget too. A
disagreement needs two answers, so terminating the loser after the winner is
definitive cannot hide one; `stopped=` in the `% SZS detail` line records when
the comparison was not applicable. Same problem, 109.498 s → 0.54 s.

**And a proof route the kernel refused.** `sat_backed_refutation` could not
cite a `cnf_transformation` parent, so the Tier-2 refutation route was
kernel-rejected for any problem with a conjecture — `eq_unit_ground.p` went
from `self_check=Certified` to `GaveUp` when Tier 2 started running first.
Those rules are in the parent set now, each still verified by its own
verifier; the FRAT trace is still bound to exactly the cited clauses.

## Result

Certified track, casc-30 EPS, 30 s budget:

| | solved |
|---|---|
| before (`9f92172`) | 12 / 100 |
| after (`9132b1e`) | 36 / 100 |

The 12 before were also the only source of EPS coverage in the harness, since
the ordinary portfolio cannot return `Satisfiable` at all.

## What is left

28 problems never materialize a grounding even with renaming. They split
into two groups, and only one of them is worth attacking next:

- **Infeasible for any grounder** — KRS/HWV-ar/SYO-ar (2 constants, 100–280
  variables per clause) and SYN816–SYN841 (26–48 constants, arity 40–56).
  A single atom containing every variable of a clause has one distinct
  instance per assignment, so no canonicalization helps. These need lazy
  instantiation: a CDCL search over the Herbrand atoms with clause instances
  generated on demand from the falsified clause, then an independently
  checked model. That is a research-grade tier, not a patch.
- **Just over a cap** — HWV042-2/048-2/049-2 need 6.5M instances against a
  6M cap at ~8 GB peak, and SYN514-1/SYN422-1 need 1.1e10 and 7.2e8. The
  first three are affordable under a 128 GB allowance and are worth a cap
  bump; the other two are not, and would fall into the lazy tier.

The Tier-2 caps were re-sized from measurement for this work (16 384 atoms /
2M instances → 400k / 6M). With the grounding no longer inflated by renaming
duplicates, the *atom* count became the binding constraint rather than the
instance count, and the atom set is not what limits memory — CaDiCaL's arena
on million-event UNSAT proofs is.

## Reproducing

```bash
cargo build --release --bin mrs

# certified track alone, casc-sim at the CASC limit
MRS_HARDWARE=casc-sim MRS_SIM_TIME_FACTOR=1 ./target/release/mrs \
    --time 120 --workers 1 --hardware casc-sim --schedule casc_eps \
    --strategy 1 --certify-ordered EPS/<problem>.p

# the harness route, with the refusal reason per problem
TRACE_CERTIFY=1 ./target/release/mrs --time 60 --workers 1 \
    --schedule casc_eps --strategy 1 --certify-ordered EPS/<problem>.p 2>&1 \
    | grep CERTIFY

# the full division
MRS_HARDWARE=casc-sim MRS_SIM_TIME_FACTOR=1 MRS_WORKERS=2 \
    crates/mrs-bench/casc.sh --systems mrs --divisions eps --casc-times \
    --jobs 1 --output results/eps-casc-sim
```

On a host with fewer than 8 physical cores, casc-sim warns that the worker
count is not representative of a CASC entry and pins nothing. That does not
affect the certified track, which is a single thread either way — which is
precisely why measuring it here transfers.
