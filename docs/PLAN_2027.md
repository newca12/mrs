# MRS 2027 Implementation Plan

This document defines the engineering plan for the 2027 CASC and ProoVer
competitions. It separates two goals that must not be conflated:

1. **CASC performance:** maximize the number of problems solved by the fast
   parallel `mrs` prover.
2. **Proof trust:** make every proof accepted by the self-checking mode
   independently checkable by a small proof kernel.

The current `feat/proover-max-score` branch is a strong ProoVer competition
candidate, but it is not yet the final self-verifying architecture. In
particular, the current verifier still has heuristic and same-engine fallback
paths, and AVATAR/CWA proof output does not yet preserve a complete SAT-level
certificate. The implementation below addresses those limitations in stages.

## Current Status

Updated after the strict-kernel milestone on 2026-08-01.

### Completed

- **Phase 1.1:** `mrs --self-check` is fail-closed. Only a certified proof may
  emit `Theorem`/`Unsatisfiable` and proof text; inconclusive or failed checks
  emit `GaveUp`.
- **Phase 1.2:** strict provenance requires a linked problem, named leaves,
  resolved includes, and matching proof-source paths. Anonymous leaves remain
  competition-only.
- **Phase 1.3:** strict mode bypasses the legacy AVATAR/CWA structural
  shortcuts, and predicate-name-based symmetry has been removed from strict
  resolution checking. Competition mode remains unchanged for score coverage.
- **Phase 1.4:** zero `--time`/`--workers` values are rejected, strict-mode
  proof paths are collision-resistant, and strict kernel resource limits are
  explicit.
- **Phase 2:** `docs/VERIFIER_SPEC.md` defines strict, competition, and
  diagnostic trust policies.
- **Phase 3.1:** `mrs-proof-kernel` exists as a separate crate with no
  `mrs-search`, ATP, or process dependency.
- **Phase 3.2:** the kernel checks names, parent references, cycles, unique
  reachable `$false` roots, disconnected nodes, roles, provenance, source
  identity, symbol signatures/arity, and resource limits.
- **Phase 3.3:** the kernel checks named leaves, negated conjectures, NNF,
  alpha-equivalent identity, existential Skolemization with fresh witnesses
  and scope checks, including nested existentials, regrouped universals, and
  associative matrix matching and effective quantifier polarity under negation;
  complete E-style `skolemize` metadata on single-parent steps; it also checks
  fresh biconditional definitions, bounded CNF expansion, and clause
  normalization.
- **Phase 3.4:** the kernel checks resolution, factoring, equality
  resolution, equality factoring, subsumption resolution, bounded demodulation,
  and bounded superposition.
- **Phase 4.1:** the kernel checks explicit `split_component` branch contexts
  and `avatar_sat_refutation` roots; missing, duplicate, mismatched, or
  unrelated branches are rejected.
- **Phase 5:** MRS strict self-check and `mrs-proover --strict` use the
  independent kernel. Generated Socrates proofs certify end to end. The
  no-include self-check path now parses problem/proof text in memory through
  `mrs-proover::strict::verify_text`; include-bearing problems retain resolved
  loader verification.
- **Phase 6:** `mrs-proover --strict` exposes the kernel-only policy directly;
  competition mode still retains the broader ATP-backed verifier.
- **Phase 7 baseline:** adversarial tests cover forged resolution/factoring/
  superposition, anonymous provenance, source mismatch, dangling nodes,
  malformed demodulation, unsupported-rule fail-closed behavior, and a
  corpus-wide assertion that no parseable committed evil proof is certified.
  A deterministic resolution mutation harness now covers formula, sign, term,
  parent, rule, status, role, provenance, and root mutations.
  Malformed TPTP and DAG fixtures also assert fail-closed `Rejected`/
  `Inconclusive` behavior without panics.

### Still outstanding

- **Phase 1.4:** strict kernel limits currently bound work but do not expose
  per-step telemetry. Competition ATP execution now has hard Rust deadlines,
  process-group cleanup on Unix, and joined stdin/stdout workers.
- **Phase 3.3:** implement quantifier normalization and multi-parent
  definitional CNF transformations in the kernel. Fresh nested Tseitin
  definitions, transitive dependency validation, and their bounded CNF clauses
  are now certified, including flat atom/disjunction definition bodies and
  exact cited dependency closure. Single-parent existential Skolemization
  covers nested
  matrices, regrouped universals, and associative reordering; multi-parent
  Skolemization now validates Vampire-style axiom parents, dependent rewrite
  order, fresh witnesses, scope, and bounded matching. Negation-polarity
  Skolemization now propagates effective quantifier polarity through negation
  and accepts complete E-style `skolemize` metadata on single-parent steps.
- **Phase 3.4:** implement justified literal deletion. Equality factoring now
  recomputes all valid same-parent side unifications and exact disequality
  conclusions; condensation recomputes its unifying substitution and exact
  literal deletion; bounded formula-equivalence rules use independent NNF and
  AC/idempotent canonicalization; subsumption resolution is checked by
  standardized-apart multiset matching and exact target-literal deletion.
  Bounded universal `instantiate` and existential-generalization steps are now
  checked by exact substitution and witness replacement. Multi-parent
  `conjunction` now requires exact parent-part construction modulo AC order.
- **Phase 3.5:** single-parent Skolemization checks are now in the independent
  kernel, including exact arity, active-universal scope, witness distinctness,
  nested matrices, regrouped universals, and bounded AC matching. Multi-parent
  Skolemization is now covered for Vampire-style multi-parent axiom steps;
  negation-polarity variants and complete E-style `skolemize` metadata are also
  covered; incomplete/multi-parent E-style forms, general directional/quantified
  CNF fragments, and removal of production `unsafe` from the legacy verifier
  path remain.
- **Phase 4:** CWA now emits a generated roll-up ID and cites the original top
  disjunction plus every branch root. The strict kernel validates complete
  CWA-style certificates, including branch polarity, branch coverage, and
  branch-local ancestry. A linked TSTP CWA fixture and branch-polarity mutation
  regression now exercise the certificate through parsing and source checks.
  General AVATAR output still lacks complete SAT certificates.
- **Phase 5:** support stdin with explicit include roots, split search and
  verification budgets, and add strict telemetry. In-memory strict verification
  is complete for no-include inputs, and stdin now successfully verifies
  include-bearing proofs with `--include-root DIR` and resolved provenance. The
  kernel telemetry API reports elapsed time, node counts, clause-literal count,
  and verdict.
- **Phase 7:** expand the deterministic mutation harness into property-based
  tests for propositional/first-order resolution, equality, case splits,
  quantifier transformations, Skolemization, and AC normalization; fuzz
  parsing, DAG construction, lowering, and rule dispatch. The current
  corpus-wide and resolution-mutation invariants are enforced: no parseable
  committed evil proof or tested mutation is strictly certified, and malformed
  parser/DAG inputs do not panic.
- **Phase 8:** commit the complete PRV problem corpus, manifest, checksums,
  toolchain metadata, and reproducible score reports. Add explicit
  `mrs-codex --verify-mode kernel|competition|none`.
- **Phase 9:** split the current large branch into focused reviewable commits
  and pull requests before merging to `main`.

## Design Principles

- Self-verification must fail closed: no `Theorem`/`Unsatisfiable` result and
  no proof output after `Unknown`, timeout, parse failure, missing provenance,
  or verifier infrastructure failure.
- The strict self-checker must not call `mrs-search`, E prover, Vampire, or
  any other theorem prover to accept a proof.
- Every accepted inference must be checked from its actual parents and
  conclusion. Inference names and status annotations are metadata, not proof
  of correctness.
- Search optimizations may remain incomplete, but they must never change a
  soundness decision into a theorem without a certified proof.
- Keep the competition checker and strict proof kernel as separate policies.
- Freeze proof semantics before the final CASC optimization phase.
- Treat all benchmark results as reproducible experiments: record inputs,
  binary hashes, dependencies, hardware, commands, and raw outputs.

## Product Boundaries

### `mrs`

The high-performance CASC prover. It may use the existing portfolio,
AVATAR, CWA, FVO, clause sharing, AC ordering, and ML guidance. Its release
output is only a theorem in strict mode after the serialized proof has passed
the strict kernel.

### `mrs-proover`

The ProoVer competition checker. It may retain external ATP adapters and
competition-specific dialect handling for score maximization, but those paths
must be clearly labelled as competition/diagnostic behavior.

### `mrs-proof-kernel`

A new small, deterministic crate for strict proof checking. It must not depend
on `mrs-search`, external ATP binaries, or `mrs-proover` process adapters.

## Verification Policies

The implementation will expose three explicit policies:

| Policy | Purpose | External provers allowed? |
|---|---|---:|
| `StrictKernel` | `mrs --self-check` and release trust gate | No |
| `Competition` | ProoVer scoring and broad TSTP compatibility | Yes |
| `Diagnostic` | Debugging, corpus analysis, differential testing | Yes |

`MrsAtp` is a second invocation of the same MRS search engine. It is useful
for diagnostics and coverage, but it must not be described as independent
verification and must not be part of the strict-kernel trust argument.

## Phase 1: Immediate Containment

### 1.1 Fail-closed self-verification

Change the MRS self-verification guard so that only `VerifiedGood` permits a
refutation result and proof output. Treat all other outcomes as `GaveUp` in
self-check mode:

- `VerifiedBad`
- `Unknown`
- proof parse/load failure
- verifier timeout
- insufficient remaining time
- missing problem file
- malformed proof

Add an explicit `--self-check` option. Keep it opt-in until the performance
cost and proof coverage are measured. The existing CASC path must not silently
claim a theorem when the checker was skipped or inconclusive.

### 1.2 Strict provenance requirements

In strict mode, reject or return `Unknown` for:

- missing `% Proof :` header
- missing linked problem
- missing `file(...)` source on a leaf
- unresolved include files
- anonymous provenance that cannot be matched to the problem
- unsupported dialects
- unknown inference rules

The competition checker may retain conservative modulo-assumption behavior,
but that behavior is not valid for strict self-verification.

### 1.3 Disable unsafe AVATAR shortcuts

The current structural shortcuts for `split_component`,
`avatar_component_clause`, and `avatar_split_clause` must not yield strict
`Sound` merely from partial shape checks. Until explicit certificates exist,
these paths must fall through to `Unknown` or a competition-only ATP path.

Remove predicate-name-based symmetry assumptions such as treating
`distinct_points`, `distinct_lines`, or `convergent_lines` as symmetric unless
an explicit theorem/axiom justifies the rewrite.

### 1.4 Resource and process hardening

- Normalize `--workers 0` to one worker or reject it.
- Reject zero verification budgets.
- Use unique temporary proof paths.
- Ensure child ATP processes cannot survive verifier termination.
- Bound proof node count, formula depth, branch count, and allocation-heavy
  transformations.
- Return structured infrastructure errors rather than panicking.

## Phase 2: Formal Trust Model

Create `docs/VERIFIER_SPEC.md` defining:

- problem identity and include semantics
- accepted proof formats
- proof root requirements
- provenance requirements
- rule semantics
- strict versus competition behavior
- `Certified`, `Rejected`, and `Inconclusive` meanings
- resource-limit behavior
- the exact claims made by the project

The outer SZS interface may map these internal results to
`VerifiedGood`/`VerifiedBad`/`Unknown`, but the kernel API should retain the
more precise distinction between an invalid proof and an inconclusive check.

## Phase 3: Independent Proof Kernel

Create:

```text
crates/mrs-proof-kernel/
```

Target dependency direction:

```text
mrs-proof-kernel -> mrs-core, mrs-tptp
mrs-proover      -> mrs-proof-kernel + optional ATP adapters
mrs              -> mrs-search + mrs-proof-kernel
```

The kernel must not depend on `mrs-search`, external ATPs, or
`mrs-proover::atp`.

### 3.1 Kernel API

Provide a deterministic API similar to:

```rust
pub fn verify_strict(
    problem: &ProblemInput,
    proof: &ProofInput,
    limits: VerificationLimits,
) -> KernelVerdict;
```

Use owned/index-based data structures where possible. Avoid production
`unsafe`, process spawning, global mutable state, and name-based trust.

### 3.2 Structural checks

Implement:

- unique formula names
- resolved parents
- acyclic parent graph
- reachable and unique certified `$false` root
- no disconnected proof fragments
- exact problem/proof identity
- role validation
- provenance validation
- symbol and arity consistency
- deterministic resource limits

### 3.3 Input and preprocessing rules

Implement and test exact checks for:

- axiom leaves
- conjecture leaves
- negated conjecture
- NNF conversion
- variable renaming
- quantifier normalization
- Skolemization
- fresh predicate definitions
- Tseitin definitions
- CNF transformations

### 3.4 Core inference rules

Implement parent-to-conclusion recomputation for:

- resolution
- factoring
- equality resolution
- demodulation
- superposition
- subsumption resolution
- justified literal deletion
- formula equivalence transformations

No rule should be accepted solely because its annotation is recognized.

### 3.5 Skolemization

Port and harden the existing structural work. Check:

- `status(esa)`
- existential variable elimination
- universal scope
- permitted binder permutation
- exact Skolem arity
- no dropped active universals
- no illegal extra variables
- no variable capture
- fresh symbols and consistent arities
- distinct witnesses for distinct existential variables
- exact matrix preservation modulo explicitly approved AC normalization

Add negative tests for every violation.

## Phase 4: Explicit AVATAR and CWA Certificates

This is the most important proof-generation change.

### 4.1 Case-split semantics

For a parent clause:

```text
L1 | L2 | ... | Ln
```

the proof must include independently refuted branches:

```text
Theory + L1 -> $false
Theory + L2 -> $false
...
Theory + Ln -> $false
```

The final case-split root is sound only when every branch is present,
correctly signed, and descends from the same parent clause.

### 4.2 Proof representation

Extend proof provenance with explicit concepts equivalent to:

```text
CaseAssumption { split_parent, branch_index }
CaseSplitRefutation { split_parent, branch_roots }
```

The final output must preserve:

- split parent
- branch index
- branch literal and polarity
- branch context
- branch root
- final case-split root

Remove fixed sentinel IDs such as `999_999_999`; allocate IDs through the
normal proof ID generator.

### 4.3 AVATAR requirements

- preserve the original unsplit clause
- emit explicit split and branch assumptions
- keep branch-local derivations separate
- emit every branch root
- emit one final case-split root
- prevent branch assumptions from becoming unconditional premises

### 4.4 CWA requirements

Retain independent branch searches for speed, but output complete branch
certificates containing the top disjunction, branch assumption, required
definitions, and branch derivation. The final root must reference every branch
root and the original top clause.

Add malicious tests for wrong polarity, missing branches, duplicate branches,
unrelated roots, false branch reuse, and arbitrary split annotations.

## Phase 5: Strict MRS Integration

The strict path must:

1. run search
2. serialize the proof
3. reparse the serialized proof
4. verify it against the original parsed problem with the kernel
5. emit `Theorem`/`Unsatisfiable` only after certification

Prefer an in-memory kernel API. If temporary files remain, use unique
`NamedTempFile` paths, content hashes, explicit include roots, and no reliance
on the current working directory.

Support stdin by verifying the in-memory original input. Require an explicit
include root when stdin uses external includes.

Split the time budget explicitly between search and verification. If the
remaining budget cannot complete verification, return `GaveUp` rather than
emitting an uncertified theorem.

Record telemetry for search time, serialization time, kernel time, proof size,
node count, branch count, and verdict.

## Phase 6: ProoVer Checker Rework

### Competition mode

Retain external E, Vampire, FMB, and dialect adapters for competition scoring,
but label them clearly. External ATP answers may improve coverage but are not
part of the strict-kernel soundness claim.

### Strict mode

- kernel only
- no `MrsAtp`
- no external ATP acceptance
- no modulo-assumption leaves
- unsupported rules become `Unknown`
- no implicit global axioms

## Phase 7: Adversarial Validation

Build a mutation tool that changes one proof property at a time:

- formula
- literal sign
- term argument
- variable/binder
- parent reference
- rule
- status
- role
- provenance
- Skolem symbol
- branch index
- branch root
- final root

Required invariant:

```text
No mutated proof may be strictly certified.
```

Add property-based tests for propositional resolution, first-order resolution,
equality, case splits, quantifier transformations, Skolemization, and AC
normalization. Fuzz parsing, DAG construction, lowering, and rule dispatch;
malformed inputs must never panic or abort the process.

The committed ProoVer corpus must include:

- all 100 PRV problem files
- all 100 proof files
- classification manifest
- expected score
- SHA-256 checksums
- generator and tool versions
- exact commands and raw outputs

Replace hardcoded scoring lists with a manifest validated for exactly 100
problems, 50 valid proofs, 50 evil proofs, and 10 locally sound mutations.

Update `run_proover_audit.sh` to distinguish:

- certified good
- confirmed bad
- unknown/unverified
- MRS timeout
- parse error
- verifier timeout
- infrastructure failure

Use distinct exit codes. A run containing only `Unknown` theorem proofs must
not be reported as a clean audit.

Make `mrs-codex` verification mode explicit:

```text
--verify-mode kernel
--verify-mode competition
--verify-mode none
```

Record MRS, kernel, competition verifier, external ATP, and timing results in
separate fields.

## Final Acceptance Gates

The project may claim to be self-verifying only when:

- no theorem is emitted after strict verification `Unknown`, error, timeout,
  missing provenance, or malformed proof
- no adversarial mutation is strictly certified
- AVATAR/CWA proofs carry explicit complete case-split certificates
- the strict kernel has no `mrs-search` dependency
- freshly serialized MRS proofs pass the kernel from a fresh parse
- the complete PRV corpus is reproducible from committed inputs and checksums
- audits distinguish verified from merely not disproven
- CASC solved counts do not materially regress
- all required Nix-wrapped checks pass

Strict self-check should remain opt-in until the kernel certifies the supported
MRS proof language and its performance cost is measured. It may then become
the default for development and, after a final competition rehearsal, for the
competition release.
